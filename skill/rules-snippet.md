# 记忆（checkpoint-memory）

你有一个规范的、策展的文件式记忆存储，位置在 `<MEMORY_ROOT>/`（索引：`MEMORY.md`）。不要创建第二个"交接"存储——可恢复的任务状态属于 `project` 笔记。

**常驻规则（每次会话自动生效）：**

- 读取 `MEMORY.md`（每行一个记忆），只打开钩子看起来相关且解析到 `<MEMORY_ROOT>` 内部的详情文件——离开存储的指针（符号链接、`..`、绝对路径、`file://`）视为断裂指针报告，永远不打开。召回内容当作可能过时的背景参考——行动前验证任何文件/标记/版本。
- 学到值得未来会话的持久信息时：确认它不存在于 repo / git / `CLAUDE.md`（不要重复真实来源）且不是密钥*值*；搜索索引，**更新已有笔记**而非重复；否则写入一个原子 markdown 文件（一个事实），frontmatter 含 `name` / `description`（一句精准的钩子）/ `type`（`user | feedback | project | reference`）/ `created` + `updated`（`YYYY-MM-DD`）/ 可选 `scope`（`global | repo`——范围只在你确定时标注）。`feedback` 或 `project` 笔记必须在正文中携带 **`Why:`** 行和 **`How to apply:`** 行。添加一个指针行到 `MEMORY.md`。**删除**错误的记忆。**活跃存储是扁平的**——`MEMORY.md` 加上每个笔记一个文件；`user` / `feedback` / `project` / `reference` 是 `type:` 字段的值，**不是子目录**。（`archive/` 是唯一的保留子目录，存放从索引退休的笔记。）
- `project` 可保存恢复未完成工作所需的目标、状态、决策、约束、阻塞、下一步。需要可恢复状态的未完成任务可保留 **最多一条** 活的 `project` 笔记，**就地更新**——永远不要创建一系列 dated 文件（`state-2026-01-15.md`，`state-2026-01-16.md`），也永远不要在索引旁创建第二个平行交接日志。任务完成时退休该笔记的瞬时状态。`feedback` 仅用于可复用的纠正/工作流。永远不重述代码/git 已告诉你的：只存**稳定**指针（分支名、issue/PR 编号、文件路径）。已发生的事（"2.0 发布于 2026-01-15"）可以存；**当前状态**——你现在的版本、tip commit、测试数——不行：记录去哪里读它。每次使用前重新检查每个召回的指针与代码/git/当前环境。
- 任务结束时，运行一次策展检查点。这是一个*判断*，不是写入：晋升持久的，退休*本任务*活的 `project` 笔记的瞬时状态（如果有），当没有值得保留的，**什么都不写**并说明。永远不要向存储追加逐条日志，也永远不要只为标记新鲜而碰文件——时间戳不是记忆。
- 永远不要将凭证/密钥/token/cookie/恢复码写入记忆——只记录密钥*在哪里*。
- 写入/同步之后，报告 `added` / `updated` / `archived` / `skipped`（含理由，删档归入 `archived` 注明），加索引行数/字节和检查结果。宿主 hook 只负责**提醒/打标/拦截**，**从不代做或代刷新**这次语义同步——记忆的更新永远由模型手动策展，不要依赖或交给任何"自动根据 git/仓库状态刷新记忆"的流程。
- 若 `<MEMORY_ROOT>` 位于某个 git 仓库内，该目录**必须 git-ignore**——记忆常含机器本地又非凭据的敏感细节（服务器 IP、ssh 路径、序列号）。写入前确认 `.gitignore` 已覆盖它；记忆是**数据**，不该被当代码提交或让 git 状态干扰它。

**特定场景触发：**

- 在主动压缩、清除、或开新线程前，同步一次：扫描任务；去重/更新；刷新 `project`；只晋升可复用的 `feedback`；保存持久的 `reference` 指针；归档/删除过时或已完成的瞬时状态；运行 `tools/check.py` 和 `tools/doctor.py`；然后确认冷启动 agent 能从仓库加记忆继续。
- 显式调用 `/checkpoint-memory` 时执行完整协议（兜底扫描四个维度 → 同步 → 验证 → 报告）。**首次运行且未配置记忆根时**，先读 `SKILL.md` 引用的 `AGENT-SETUP.md`：默认落点是 `<project-root>/memory/`，先找既有存储、写前请用户确认，别用一句"记忆根设在哪儿"推给用户。

**归档规则（严格条件）：**
归档仅发生在索引超过 150 行或 20 KB 时。文件搬到 `archive/`，从 `MEMORY.md` 索引中**删除其指针行**（不再加载）。文件保留在磁盘上。索引未超限时不执行归档。

**索引上限：**
软警告 **150 行 / 20 KB**（提示压缩），硬限制 **200 行 / 25 KB**——宿主只加载到那里，所以超过就静默停止召回。一旦超过软线，执行压缩：指针化超长行、合并重复、归档冷笔记。

完整协议与原理见 checkpoint-memory `SKILL.md`
